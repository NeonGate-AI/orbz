# Code Style

## Purpose

This document defines the mandatory coding standards for every source file in this repository.

These rules establish a single, consistent style for writing code. Every contribution, whether written by a human or generated by an AI agent, must follow them without exception.

## Scope

These rules apply only to source code.

They define how code is written, structured, formatted, and organized.

They do not define:

- Architecture
- Product behavior
- Business rules
- Specifications
- Tooling
- CI/CD
- Git workflows

Those concerns are documented separately.

## Rule Application

Every rule in this document is mandatory.

When multiple implementations are possible, use the one defined in this document.

Do not introduce alternative styles, patterns, or conventions unless this document is updated first.

## 1. Import Paths

### Description

Use `./` imports only for sibling modules.

Do not use `../` imports.

Use path aliases for every non-sibling import.

### Incorrect

```ts
import { Button } from '../ui/button'
import { format } from '../../lib/format'
```

### Correct

```ts
import { Button } from '@ui'
import { format } from '@lib/format'
```

## 2. String Quotes

### Description

Use single quotes for every string literal in source code.

Use the quote style required by the file format.

### Incorrect

```ts
const name = "John"
const title = "Sim"
```

### Correct

```ts
const name = 'John'
const title = 'Sim'
```

```tsx
<Button aria-label="Continue" />
```

```json
{

    "strict": true
  }
}
```

## 3. Import Order

### Description

Group imports in the following order:

1. Third-party modules.
2. Absolute imports.
3. Relative imports.

Sort imports alphabetically within each group.

### Incorrect

```ts
import { Button } from '@ui'
import { useState } from 'react'
import { Header } from './header'
import { z } from 'zod'
```

### Correct

```ts
import { useState } from 'react'
import { z } from 'zod'

import { Button } from '@ui'

import { Header } from './header'
```
